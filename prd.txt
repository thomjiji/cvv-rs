# cvv-rs PRD

## Background

DIT 日常工作中缺乏稳定可靠的跨平台拷贝工具。Windows 有 TeraCopy，macOS 无可用方案
（Offshoot 收费且界面简陋，hashfile 格式不适配工作流）。cvv 填补这个空缺。

主要场景：in-house 素材分发。将数据备份 HDD 直连工位，本地拷贝到 DAS 工作盘。
数据量可达数 TB，HDD 读取约 200MB/s，运行周期长，对稳定性要求极高。

不用于存储卡初始 offload（那一步使用 Offload Manager 等商用软件）。

## CLI Interface

    cvv <source> <target>...

- source: 文件或目录
- target: 一个或多个目标路径（fan-out）
- `-m <mode>`: 预声明校验模式，跳过拷贝后的交互提示
  - `source`: 重读源 + 所有目标，重新算哈希比对（最严格）
  - `target`: 仅重读目标，与 in-flight 哈希比对
  - `transfer`: 仅比对字节数，不校验

不指定 `-m` 时，拷贝完成后交互式 prompt：

    Verify? [Y/n]          <- 默认 Y，回车即可
    Mode? (source/target)  <- 默认 target，回车即可

用户两次回车即可走默认校验流程。

## Core Features

### 1. Recursive Directory Copy
- source 为目录时递归遍历，在 target 重建目录结构
- source 为文件时直接拷贝

### 2. Fan-out (One-to-Many)
- 源只读一次，同时写 N 个目标
- 节省源盘读取带宽

### 3. Verification Modes
三种校验模式，均在所有文件拷贝完成后统一执行：

- **source**: 重新读取源文件和所有目标文件，各自计算哈希，全部比对
- **target**: 仅重新读取目标文件，计算哈希，与拷贝过程中 in-flight 源哈希比对
- **transfer**: 不重新读取，仅比对字节数是否匹配

哈希算法：xxHash3-64（当前唯一支持）

### 4. Atomic Copy
- 写入临时文件（`.tmp` 后缀），完成后 rename
- 保证目标位置要么存在完整文件，要么不存在
- 断电/crash 时不会留下半成品文件

### 5. Metadata Preservation
- 拷贝时保留源文件的修改时间和访问时间

### 6. Collision Detection
- 目标已存在同名 + 同大小文件 → 跳过
- 目标已存在同名但大小不匹配 → 覆盖
- 残留 `.tmp` 文件 → 清理并重新拷贝

### 7. Hash File Generation
拷贝完成后生成 TeraCopy 兼容的 hashfile。格式：

    ; xxHash3-64 checksums generated by cvv
    ;

    HASH *relative/path/to/file.mp4

- 后缀：`.xxh3`
- 哈希值大写十六进制
- 路径使用正斜杠、相对于 target 根目录

### 8. Progress Display
简单文本输出，不使用 fancy 进度条库：

拷贝阶段：

    [123/12394] Copying CESD-250.mp4  45.2%  182.3 MB/s
    Overall: 3.2%

校验阶段同理：

    [123/12394] Verifying CESD-250.mp4  45.2%  182.3 MB/s
    Overall: 3.2%

### 9. Robustness
- 长时间运行稳定性（数小时级别）
- 中断处理：Ctrl+C 安全退出，清理 .tmp
- Crash 恢复：重新运行时通过 collision detection 跳过已完成文件
